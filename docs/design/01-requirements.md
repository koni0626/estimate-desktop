# 1. 要求・機能一覧

## 1.1 目的・対象者

個人事業主から小規模チームまで、見積の作成、承認、発行、受注・請求へのつながりを一つの画面で追えるようにする。複数の会社が同じアプリを使っても、各社の業務データは分離する。会社は法人だけでなく屋号を持つ個人事業も含む。

主な利用者は会社管理者、一般担当者、課管理者、部管理者。小規模な事業者は会社管理者1人で開始できる。役割と実際の承認者は別概念とする。

## 1.2 対象機能と受入条件

|ID|機能|受入条件|
|---|---|---|
|FR-01|利用者の確認|ブラウザー版・複数ユーザーDBではユーザー名・パスワードでログインする。個人用デスクトップ版は起動ごとの秘密値で自動再開し、パスワード入力を求めない|
|FR-02|会社・組織|会社別に部・課・メンバーを登録でき、他社IDを指定しても情報を取得できない|
|FR-03|取引先|会社内で取引先を作成・編集でき、見積には発行時点の宛先を保持する|
|FR-04|案件・要望|案件を作り、要望と合意内容・版を記録し、見積に対象要望を紐付けられる|
|FR-05|見積作成|件名、有効期限、条件、明細を入力し下書き保存できる。案件なしでも作成できる|
|FR-06|金額計算|数量×単価、税率別税額、合計をサーバーで再計算し、画面送信の合計を信用しない|
|FR-07|承認|会社別に承認なし／1〜10段階の順次承認を選べる。自己承認・段階飛ばしを拒否する|
|FR-08|発行・PDF|発行で見積番号とPDFを確定し、再ダウンロード時に同じPDFを返す|
|FR-09|印鑑画像|会社印・屋号印の登録と見積版ごとの任意表示。画像なしでも発行できる|
|FR-10|版・履歴|発行後は改版で新しい下書きを作り、旧版・承認・操作履歴を残す|
|FR-11|受注|発行済み見積の特定版から受注を作り、合意した版と金額を保持する|
|FR-12|請求・入金|受注から請求書を作成・PDF発行し、全額入金日を手動で記録できる|
|FR-13|添付|案件に複数資料をドラッグ＆ドロップで追加・取得・削除できる|
|FR-14|初回セットアップ|空DBのときだけ本人が事業者と最初の会社管理者を登録でき、登録後は同じ入口から追加登録できない。デスクトップ版では事業者名・表示名だけで完了する|

## 1.3 権限

|役割|見積・案件の通常閲覧範囲|主な操作|
|---|---|---|
|一般担当者|所属課。課なしでは自分が担当するもの|作成、自分が担当する編集可能な見積の更新・申請・発行|
|課管理者|所属課|課内の見積と案件の管理|
|部管理者|所属部|部内の見積と案件の管理|
|会社管理者|自社全体|会社設定、部・課・メンバー、見積の管理|

承認者に指名された利用者は、その申請対象の見積版を確認できる。ただし、これを理由に別課の案件一覧や取引先以外の情報全体へ権限を広げない。PDFも元の見積または請求の閲覧権限に従う。会社境界はすべての業務APIでサーバー側が判定する。

## 1.4 業務ルール

- 金額は日本円・税抜入力。数量は正の値で小数3桁、単価は0以上で小数2桁。税率は0%、8%、10%。明細ごとに円単位で四捨五入し、税率別の明細金額合計から税額を切り捨てる。
- 見積は `下書き → 承認待ち → 承認済み → 発行済み` を基本とする。承認なしなら下書きから発行可能。差戻し・取下げ・承認解除を経た編集は再申請する。
- 発行済み見積は直接編集しない。改版で次の版を作る。複製は別の見積とし、元の見積番号・承認結果を引き継がない。
- 見積発行は顧客への送信ではない。受注は発行済み版に対して登録する。請求の入金は全額確認のみで、部分入金の管理は対象外。
- 印鑑画像は帳票上の任意表示であり、承認や電子署名の代わりにはならない。

## 1.5 非機能・範囲外

Python 3.14 / FastAPI / SQLAlchemy 2 / Alembic / SQLite 3 / React / TypeScript / Vite を使う。利用環境は個人のローカルPCの日本語ブラウザーを想定し、起動ポートはWeb 5185、API 8005。データは `data/estimate2.sqlite3` に保存する。

SSO、初回セットアップ以外の公開ユーザー登録、招待メール、パスワード再設定、メールによる見積送付、外貨、価格マスター、発注管理、部分入金、決済、帳票デザイナーは対象外。一般公開に必要なレート制限、監視、バックアップ・復元、運営者管理、性能試験も未整備である。
